# 08. 検証方針

## 8.1 なぜ必要か

本作のバグは「動かない」ではなく「**成立しないフロアが稀に生成される**」「**深度20階でだけ
バランスが破綻する**」という形で出る。どちらも手で遊んでいて見つかる保証がない。

そこで、**不変条件を列挙し、それを機械的に反復検査する**方針を採る。

## 8.2 テストの層

| 層 | 対象 | 手段 |
|---|---|---|
| 不変条件テスト | ダンジョン生成・ターン処理・戦闘 | `vitest`（ヘッドレス、多数のシードで反復） |
| バランス検算 | 難易度カーブ | [`tools/difficulty-model.mjs`](../tools/difficulty-model.mjs) |
| 単一ファイル検証 | ビルド成果物 | ビルド後スクリプト |
| 手動プレイテスト | 手触り・面白さ | チェックリスト |

### テストの置き場所

```
tests/
├─ helpers/bot.ts          「上手くないプレイヤー」の自動プレイヤー
├─ helpers/expectations.ts  期待値を実装から独立に導出する小道具
├─ dungeon.test.ts          生成の不変条件・決定性
├─ spawn.test.ts            敵とエンティティの配置
├─ turn.test.ts             ターン消費・選択待ち・階層遷移
├─ loot.test.ts             インベントリ・アイテム・装備・宝箱
├─ progression.test.ts      派生値の再計算・パーク
├─ equipment.test.ts        装備の比較と持ち替えの判断
├─ abilities.test.ts        出現テーブル・敵の特殊能力・継続効果
├─ events.test.ts           ランダムイベント・巻物・鍵
├─ achievements.test.ts     実績の判定と永続化
├─ sprites.test.ts          ドット絵の形式と識別性
├─ regression.test.ts       一度本番に入った不具合の退行テスト
├─ storage.test.ts          設定と記録の永続化
└─ difficulty.test.ts       到達階層の分布（受け入れ基準）
```

```bash
npm test            # 全検査
npm run measure 60  # 難易度の実測値を人が読む形で出す
```

### 依存関係について

`vitest` は **devDependencies** に入れる。
「ランタイム依存ゼロ」は出荷される `dist/delve.html` の制約であり、
開発時のツールには適用されない（`vite` / `typescript` と同じ扱い）。

`src/game/` と `src/core/` が DOM に触れないという境界（→ [02](02-architecture.md)）を
守っている限り、これらのモジュールはブラウザなしでそのままテストできる。
**この境界の実利がここにある。**

## 8.3 不変条件

### ダンジョン生成（→ [06](06-dungeon-generation.md)）

多数のシード × 多数の階層で反復し、すべてについて次を満たすこと。

- [ ] `stairs` が `start` から BFS で到達可能
- [ ] `start` と `stairs` の BFS 距離が閾値（`(width + height) / 4`）以上
- [ ] 外周 1 マスがすべて `wall`
- [ ] 敵とエンティティがすべて到達可能マス上にある
- [ ] 同一マスに複数のエンティティが存在しない
- [ ] 敵が `start` から `SPAWN_MIN_DISTANCE` 以上離れている
- [ ] 同一シード・同一階層で生成結果が完全に一致する（決定性）

> ✅ [`tests/dungeon.test.ts`](../tests/dungeon.test.ts) で 200 シード × 7 階層を検査している。

### エンティティの配置

- [ ] 床の物が到達可能マス上にある
- [ ] `start` から `SPAWN_MIN_DISTANCE` 以上離れている
- [ ] 敵と同じマスに**生成されない**（生成後に敵が上を通るのは仕様）
- [ ] 個数が `potionsPerFloor(floor)` と一致する

> ✅ [`tests/spawn.test.ts`](../tests/spawn.test.ts) で 40 シード × 30 階層を検査している。

### ターン処理・戦闘

- [ ] 壁への移動でターンが消費されない
- [ ] 階段を降りた直後のターンに、新フロアの敵が行動しない
- [ ] HP が 0 になった敵が次のターンに行動しない
- [ ] 2体の敵が同じマスに重ならない
- [ ] 敵がプレイヤーのマスに侵入しない
- [ ] ダメージが常に 1 以上（`MIN_DAMAGE` の保証）
- [ ] `phase === 'dead'` の間、移動入力が状態を変えない
- [ ] 空のインベントリスロットを使ってもターンを消費しない
- [ ] アイテムの使用はターンを消費する
- [ ] **効果がない使用（満タンでのポーション）はアイテムもターンも消費しない**
- [ ] **1スロットの所持数が `MAX_STACK` を超えない。溢れたら次の空きスロットへ送る**
- [ ] **全スロットが埋まったら床に残り、`log.inventoryFull` が出る**
- [ ] **ターンを消費しない操作を連打しても、直前と同じログが積み重ならない**
- [ ] **爆弾で倒した敵からも経験値とゴールドが入る**（HP を直接引かず damageEnemy を通す）
- [ ] **爆弾は外周の壁を壊さない**
- [ ] **選択待ち中は移動・待機ができず、範囲外の選択でモーダルが閉じない**
- [ ] **命中ログが撃破ログより先に記録される**（因果の順に読める）
- [ ] **どのスロットにも「拾うと以降すべて拒否される」装備が存在しない**
- [ ] **上位互換は尋ねず自動装備、下位互換は尋ねず床に残す、トレードオフだけ尋ねる**
- [ ] **一度断った組み合わせは尋ね直さないが、装備が変われば再び尋ねる**
- [ ] **1ターンで複数レベル上がっても選択が取りこぼされない**
- [ ] **装備を着けて外すと派生値が元に戻る**（補正の引き忘れがない）
- [ ] **最大HPが下がったときに現在HPが超過しない**
- [ ] **割合補正が切り捨てで消えない**（攻撃力8に +10% で数字が動くこと）

### 出現テーブル

- [ ] **どの敵も `minFloor` より浅い階には出ない**（重み付けとは別の判定）
- [ ] ボスは5の倍数階にだけ、1体だけ出る
- [ ] 通常のスポーンプールにボスが混ざらない

> ⚠️ ガウス重みの裾は浅い階まで伸びる。`spawnWeight` に下限判定が無いと
> 1階に Warden が湧く。Phase 2 までは能力持ちがプールから除外されていたため
> 露見しなかった（→ [07](07-difficulty.md)）。

### 敵の特殊能力と継続効果

- [ ] Skeleton は一度だけ復活し、復活時は撃破として数えない
- [ ] Slime の子は分裂しない。経験値の総取得量が親を超えない
- [ ] **プレイヤーの行動中に生まれた敵は、そのターンに行動しない**
      （分裂やイベントの番人が「無料の攻撃」にならない）
- [ ] 防御態勢は被ダメージを半減する
- [ ] **ボスの激昂の倍率がちょうど1回だけ掛かる**
      （`attack` と `rage` の両方に持たせると 1.5 のつもりが 2.25 になる）
- [ ] 継続ダメージで倒しても経験値とゴールドが入る
- [ ] 継続効果の重ねがけは加算せず、長い方・強い方を採る
- [ ] 鈍足は行動回数を減らす
- [ ] Shield は3ターンに1回だけ無効化する

### イベント・巻物・鍵

- [ ] **踏んだだけでは効果が起きず、選択待ちになる**
- [ ] 立ち去ればプレイヤーの状態が一切変わらない
- [ ] どの選択肢を選んでもイベントのマスは消える（賭け直せない）
- [ ] イベントで湧いた敵はプレイヤーの隣には出ない
- [ ] 祭壇の祝福と呪いがレベルアップで消えない（`bonuses` が再計算に載る）
- [ ] 巻物は必ず何かを起こし、消費される
- [ ] 鍵なしでは施錠された宝箱が開かず、宝箱は床に残る
- [ ] **同じイベントのマスを踏み直しても選択は1つしか積まれない**
      （ターンを消費しない移動ではモーダルが開かないため、二重に積みうる）
- [ ] **イベントで湧かせる敵も `minFloor` を破らない**
      （種類を指定できる経路が抜け道になっていた）
- [ ] **レア以上が存在しない階では宝箱を施錠しない / 鍵も落とさない**

### 入力

- [ ] キーリピートで連続移動できる
- [ ] **キーリピートではアイテムを使用できない（単発の押下のみ）**
- [ ] 被弾・新しい敵の出現・階層移動でリピートが中断される

### 到達可能性の通しテスト

BFS で階段を目指す自動プレイヤーを走らせ、**30 階まで到達できること**。
これは生成・移動・階層遷移・スポーン・拾得を一度に通す統合テストになる。

> 確認済み（毎ターン HP を回復させた状態で 30 階まで、進行不能 0）。

> ⚠️ 注意: ボットの HP を `999999` に設定しても、レベルアップ時に
> `maxHp` がレベルから引き直されるため上書きされる。不死にするには
> **毎ターン `hp = maxHp` を代入する**こと。これを忘れると
> 「深部で詰まった」ように見えて、実際は単に死んでいる。

### 実績

- [ ] 一度解除したものは二度と返さない
- [ ] 累計は「保存済み + 進行中の Run」で見る（100体目を死亡まで待たせない）
- [ ] 深さの実績は到達最深階で判定する（現在階ではない）
- [ ] **判定が状態を変えない**（純粋な述語である）
- [ ] 解除した瞬間に保存され、Run の記録を書いても消えない
- [ ] 保存順に依らず定義順に正規化される
- [ ] 知らない id や実績フィールドの無い古い記録でも起動する

### 演出と音

- [ ] 演出クラスがすべてゲーム状態から導出されている（UI にフラグを持たない）
- [ ] **巻物のハズレで赤いフラッシュが出る**（ログだけでは見落とす）
- [ ] **そのときダメージ数値は出さない**（HP は減っていない）
- [ ] 巻物の当たりでは赤いフラッシュを出さない
- [ ] **当たりの5種すべてが、それぞれ違う盤面演出を出す**（同じ絵で違う出来事を表さない）
- [ ] ハズレでは盤面演出を出さない
- [ ] ターンが進めば前のターンの演出は出なくなる
- [ ] `.fx` の基準 opacity が 0（アニメーションが止まっても出っぱなしにならない）
- [ ] `prefers-reduced-motion: reduce` で演出が無効化される
- [ ] 効果音の既定が OFF
- [ ] `AudioContext` を起動時に作らない（最初の操作まで待つ）
- [ ] 1ターンに鳴る音が3種類以下
- [ ] 音が出せない環境でも例外を投げずにゲームが続く
- [ ] **ログが上限に達しても新規エントリを取り出せる**（長さではなく id で差分を取る）
- [ ] **設定を有効にしただけでは `AudioContext` を作らない**
- [ ] **実績のログにプレースホルダが残らない**（id を ui/ で名前に引き当てる）
- [ ] **倒した敵もそのターンの描画までは配列に残る**（とどめの一撃のダメージ数値）

### ドット絵

- [ ] すべてのスプライトが 16x16 で、未定義のパレット番号を含まない
- [ ] 歩行アニメーションが 2 フレーム
- [ ] **歩行フレーム間で上半分が完全に一致する**（変わると痙攣に見える）
- [ ] **盤面に立つものの外接矩形の中心が、画面中心から1px以内**
      （偏ると絵全体が傾いて見える）
- [ ] **回復量が違うアイテムは瓶の大きさも違う**（色だけでは暗所で見分けられない）
- [ ] 敵が互いに異なる輪郭を持つ

### アイテムの名前と効果

- [ ] マウスではホバーで説明が出て、クリックで即使用できる
- [ ] **アイコン（SVG）をクリックしても使用できる**
      （`instanceof HTMLElement` で絞ると SVG が弾かれる）
- [ ] タッチでは1回目のタップで説明、2回目で使用
- [ ] 別のスロットをタップしたら、そちらの選択に移る（使わない）
- [ ] 説明の数値が定数から組み立てられている（文言に直接書かない）
- [ ] すべてのアイテムに説明があり、プレースホルダが残らない

### ログの表示

- [ ] **自動プレイで積まれた全てのログが、両言語で `{...}` を残さず描画できる**
- [ ] 拾ったアイテムの名前がログに出る（特定のアイテム名を直書きしていない）
- [ ] 実績のログに実績名が出る
- [ ] イベント・巻物のログが両言語で破綻しない

> `game/` は識別子だけを積み、名前は `ui/logline.ts` が引き当てる。
> この対応が抜けると `{item}` や `{name}` がそのまま画面に出る。
> **渡した params が使われていない**形なので型では防げない。

### スタックの上限

- [ ] 上限を超えたら別のスロットに分かれる（仕様）
- [ ] 上限に達したスタックは個数の色が変わり、説明に `所持 n/上限` が出る

### アイテムを捨てる

- [ ] 捨てたアイテムは床に残る（消滅しない）
- [ ] 捨てたものを拾い直せる
- [ ] **足元が埋まっていれば隣のマスへ置く**（1マスに2つ置かない）
- [ ] 置き場所が無ければ捨てられず、アイテムも消えない
- [ ] 捨てるとターンを消費する
- [ ] 空のスロットではターンを消費しない

### キーボード配列

- [ ] **数字キーの判定が `event.code`**（`event.key` では配列で壊れる）
- [ ] AZERTY 配列（`code: Digit1`, `key: '&'`）でもアイテムを使える
- [ ] US 配列（`code: Digit1`, `key: '!'`, shift）で捨てられる
- [ ] `Shift` + WASD では移動しない

### 難易度の到達階層分布

「上手くないプレイヤー」を近似したボットで 60 回プレイし、分布を取る（→ [07 §7.8](07-difficulty.md)）。

- [ ] 中央値が 10〜15 階に入る
- [ ] 1〜4 階での死亡が全体の 1 割未満
- [ ] 最深が 40 階未満（深部でスケーリングが効いている）
- [ ] 進行不能になる run がない
- [ ] 回復を無駄に使うと平均到達階層が下がる（腕が結果に効く）

> ✅ [`tests/difficulty.test.ts`](../tests/difficulty.test.ts)。
> **ボットは意図的に下手に作ってある** — 逃げない、通路に誘い込まない、囲まれても引かない。
> ここを賢くすると「上手い人の到達階層」を測ることになり、目標とずれる。

> ⚠️ ボットを書くときの落とし穴: 拾えなかった物（弱い装備・満杯で入らないアイテム）を
> 目標にし続けると、その上で永久に往復する。一度踏んだ物は目標から外すこと。
> これを忘れると「難易度が急に下がった」ように見える測定結果が出る。

### 永続化

- [ ] 壊れた JSON が入っていても起動する（初期値にフォールバック）
- [ ] `version` が一致しない場合に無視して初期値を使う
- [ ] 負の値や型違いの値を 0 に丸める
- [ ] localStorage が使えない環境で例外を投げずに動作する
- [ ] ベスト記録が下がらない / 累計が積み上がる

> ✅ [`tests/storage.test.ts`](../tests/storage.test.ts)。
> Node には localStorage がないので、テストごとに差し替えている。

## 8.4 バランス検算

数値を変更したら必ず実行する。手順は [07 §7.7](07-difficulty.md) を参照。

```bash
node tools/difficulty-model.mjs
```

Margin の目標比が 0.7〜1.5 の範囲を外れた階層があれば、原因を特定してから進める。

## 8.5 単一ファイル検証

`npm run build` の後、以下を確認する。**この検証はここでしか行えない。**

- [ ] `dist/` の中身が `delve.html` 1 つだけ
- [ ] `delve.html` に `src=` / `href=` による外部参照が 1 つも残っていない
- [ ] `file://` で直接開いて起動する（開発サーバ経由でのみ動く状態になっていないか）
- [ ] コンソールにエラーが出ない

外部参照の検査はコマンドで機械的に行える。

```bash
grep -oE '(src|href)="[^"]*"' dist/delve.html
```

`<link rel="icon" href="data:...">` は data URI なので外部参照ではない。
検査時はこれを除外する。

## 8.6 手動プレイテストのチェックリスト

機械では測れないものだけを見る。

### 手触り

- [ ] キーを押してから画面が変わるまでに引っかかりを感じない
- [ ] 押しっぱなしの連続移動が、危険（被弾・敵の出現）で確実に止まる
- [ ] 歩行の 2 フレーム切り替えが「歩いている」ように見える（痙攣して見えない）
- [ ] 死亡から次のプレイ開始まで 1 アクションで戻れる

### 難易度（→ [07](07-difficulty.md)）

- [ ] 3 回プレイして、死亡階層が 10〜15 に分布する
- [ ] 1〜3 階で死ぬことがない
- [ ] 深い階で「固いだけの敵を延々殴っている」感覚がない（TTK が伸びていない）

### 判断の発生（→ [01 §1.3](01-requirements.md)）

- [ ] 「進むか戻るか」で迷う場面が 1 プレイに複数回ある
- [ ] 回復アイテムを使うタイミングで迷う
- [ ] 死んだ直後に「次はこうしよう」と具体的な作戦が浮かぶ

最後の項目が満たせないなら、それはバランスではなく**設計の失敗**を意味する。
