# 09. 実装ロードマップ

「機能を大量に詰め込んだゲーム」ではなく「ルールは単純だが毎回違う展開になるゲーム」を目指す。
そのため **基本ループを確実に完成させてから要素を積む**。各フェーズの終わりで必ず遊べる状態を保つ。

### 実測で見つけた問題（記録）

| 症状 | 原因 |
|---|---|
| 39/40 の run が測定上限 80 階に到達 | Phase 1 の係数のまま装備・パークを足したため、防御力が敵の攻撃力を追い越し被ダメージが下限1に張り付いた（→ [07 §7.3](07-difficulty.md)） |
| 中央値9・最深42階まで散る | 線形スケーリングでは序盤が厳しく深部が緩い逆S字になる。二次の項で解消 |
| `Sharpened`（+10%）を取っても数字が動かない | 割合補正の切り捨て。`floor(8 × 1.1) = 8`。四捨五入 + 最低 +1 保証に変更 |
| Swift Step で動いても視界が更新されない | `updateVisibility` をターン消費判定の後ろに置いていた |
| Ring of Vigor を拾うと他の指輪が二度と装備されない | 単一の総合スコアで順序を付けていた。支配関係だけを見て、トレードオフはプレイヤーに選ばせる形に変更 |
| 撃破ログが命中ログより先に出る | `damageEnemy` が撃破とレベルアップまで処理するのに、命中ログを後に書いていた |

### 実測で見つけた問題（記録）

| 症状 | 原因 |
|---|---|
| 1階で Warden に瞬殺される（序盤の死亡が14%） | **`spawnWeight` に `minFloor` の下限判定が無かった**。ガウス重みの裾は浅い階まで伸びる。Phase 2 までは能力持ちがプールから除外されていたため露見していなかった。重み付けは「出やすさ」を決めるものであって「出てよいか」は決められない |
| ボスが floor 5 で倒せない | 素の値 90/20/8 に階層係数が乗り、TTK 29ターン / TTD 2.1ターン（Margin 0.07）。素の値は「その階で成立する」大きさに置き、防御を低く保つ必要がある |
| 全ての敵が Goblin の絵で描かれる | `ENEMY_SPRITE_NAME` が Phase 1 の仮マッピング（未実装の種を goblin に寄せる）のままだった |
| 分裂した子がその場で殴ってくる | 敵の手番リストをプレイヤーの行動**後**に取っていた。行動前に確定させ、途中で生まれた敵は次のターンから動くようにした |
| Shrine / Cursed Chest が2〜3階で事故になる | 恒久的な代償（最大HP -10）は浅い階ほど相対的に重く、まだビルドが無いので判断もできない。出現階を5階以降に上げた |

### 演出をゲーム状態から導出する

`render()` は毎ターン innerHTML を作り直すので、**クラスを付けるだけで
CSS アニメーションが必ず先頭から再生される**。UI 側に「今アニメーション中か」を
持つ必要がない。

そのために `Actor.hurtOnTurn` と `GameState.turn` を足した。
`hurtOnTurn === turn` なら「このターンに殴られた」と分かる。
歩行フレームを `steps % 2` から導出しているのと同じ考え方で、
**「何が起きたか」はゲーム状態の事実として持ち、演出はそこから導く**
（→ CLAUDE.md の境界5）。

ターン番号は行動の**前**に進める。そうしないと、そのターン中に起きたダメージが
複数の番号にまたがってしまう。

### 音は game/ から呼ばない

`game/` は音の存在を知らない。1ターンで積まれたログのキーを
[`ui/cues.ts`](../src/ui/cues.ts) が音に引き当てる。
新しい出来事にログを足せば音も自然に付く。

同じ音は1回にまとめ、1ターンに鳴らす数を3つまでに制限する。
1手で敵が5体動くと被弾音が5連続して耳に障る。

## 進行ルール

- 各フェーズの終わりで **必ず遊べる状態**にしてコミットする。壊れたまま次に進まない。
- バランス数値は `src/data/` のテーブルだけを触って調整する。ロジックに数値を直接書かない。
- **バランス数値を変えたら `node tools/difficulty-model.mjs` を回し、[07](07-difficulty.md) の表を更新する。**
- 新しい敵・装備・アイテムの追加が、テーブルへの 1 エントリ追加で済む形を維持する。
  そうなっていなければ設計を直す。
- 演出は最後。ゲームプレイが面白くなる前に見た目を磨かない。
  ただし**ドット絵と歩行アニメーションは演出ではなく識別性の要件**なので Phase 1 に含める。
