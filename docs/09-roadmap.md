# 09. 実装ロードマップ

「機能を大量に詰め込んだゲーム」ではなく「ルールは単純だが毎回違う展開になるゲーム」を目指す。
そのため **基本ループを確実に完成させてから要素を積む**。各フェーズの終わりで必ず遊べる状態を保つ。

## Phase 1 — 基本ループとドット絵 ★最優先

> 移動 → 敵 → 戦闘 → 階段 → 次の階

### 完了済み

| 項目 | 内容 |
|---|---|
| 基盤 | 型定義 / 定数 / seeded RNG / ログ |
| ダンジョン | 部屋 + 通路生成、到達可能性保証、階段配置、フォグ |
| プレイヤー | 移動、HP、攻撃力、防御力、経験値とレベルアップ |
| 敵 | Rat / Goblin / Bat、`chase` / `swift` / `erratic` AI |
| 戦闘 | ダメージ計算、撃破、死亡 |
| 階層 | 階段で次のフロアへ、敵の階層スケーリング |
| UI | SVG ボード、HUD、ログ、死亡モーダル、キーボード / 方向パッド入力 |
| ビルド | 単一 HTML ファイル出力（`dist/delve.html`） |

### 残作業

| 項目 | 内容 | 参照 |
|---|---|---|
| ドット絵 | 16×16 スプライト定義形式と `<symbol>` 変換の実装 | [05 §5.3–5.4](05-ui-design.md) |
| ドット絵 | Player / Rat / Goblin / Bat / Wall / Floor / Stairs の作画 | [05 §5.6](05-ui-design.md) |
| 歩行アニメ | `Actor.steps` の追加と 2 フレーム切り替え | [05 §5.2](05-ui-design.md) |
| favicon | プレイヤースプライトからの data URI 生成 | [05 §5.7](05-ui-design.md) |
| 難易度 | スケーリング係数を 3 本（hp / atk / def）に分離し Phase 1 値を適用 | [07 §7.3](07-difficulty.md) |
| 難易度 | 敵の出現制御をガウス重みに差し替え | [07 §7.4](07-difficulty.md) |
| 難易度 | プレイヤー防御力の伸びを +0.5/Lv に変更 | [07 §7.5](07-difficulty.md) |
| 入力 | キーリピートの中断ルール | [05 §5.11](05-ui-design.md) |
| 敵数 | 20 階以降の上限を 12 に引き上げ | [07 §7.4](07-difficulty.md) |

**受け入れ基準**: ブラウザで開き、ドット絵のキャラが歩いて見える状態で、WASD で移動し、
敵と戦い、階段を降り、HP が 0 になったら止まる。死亡階層が 10〜15 に分布する。

## Phase 2 — 成長とループの回収

| 項目 | 内容 |
|---|---|
| パーク | レベルアップ時の 3 択（`PendingChoice` の導入） |
| レベルアップ | 回復量を全回復から最大HPの40%に変更 |
| アイテム | Potion / Bomb、インベントリ 8 スロット |
| 装備 | Weapon / Armor / Ring の 3 スロット、基本装備、床への落とし直し |
| エンティティ | 宝箱 / ゴールド / 落ちている装備・アイテム |
| 死亡 | リザルトへのスコア表示 |
| 保存 | localStorage への Best Depth / Best Score |
| テスト | `vitest` 導入とダンジョン生成の不変条件テスト移植 |
| 難易度 | 装備・パーク追加後にスケーリング係数を再検算 |

**受け入れ基準**: 死んで、記録が残り、次の Run で「今回はこのビルドを試そう」と思える。

## Phase 3 — 多様性

| 項目 | 内容 |
|---|---|
| 敵 | Skeleton / Bat / Slime / Warden の特殊能力を実装しプールに追加 |
| ボス | 5 の倍数階に出現、固有能力、確定レアドロップ |
| アイテム | Scroll / Key を追加 |
| 装備 | レア・エピック帯、特殊効果（Burn / Lifesteal / Thorns など） |
| イベント | ランダムイベント 7 種 |
| ステータス効果 | 毒 / 火傷 / 鈍足 / シールド |
| ドット絵 | Skeleton / Slime / Warden / Boss / 宝箱 / アイテム類の作画 |
| 難易度 | Phase 3 完成時の係数へ移行し再検算 |

**受け入れ基準**: 10 回プレイして、同じ展開が 2 回起きない。

## Phase 4 — 中毒性と仕上げ

| 項目 | 内容 |
|---|---|
| 実績 | 9 種の実績と解除演出 |
| 演出 | 攻撃 / 被弾 / 撃破 / 開封 / 降下 / レベルアップのアニメーション |
| サウンド | Web Audio による効果音（デフォルト OFF） |
| モバイル | タブ切替、レスポンシブの実機検証 |
| 調整 | バランス調整、UX の粗取り |

**受け入れ基準**: 「あと1階だけ」と思って実際にもう 1 回始めてしまう。

## 進行ルール

- 各フェーズの終わりで **必ず遊べる状態**にしてコミットする。壊れたまま次に進まない。
- バランス数値は `src/data/` のテーブルだけを触って調整する。ロジックに数値を直接書かない。
- **バランス数値を変えたら `node tools/difficulty-model.mjs` を回し、[07](07-difficulty.md) の表を更新する。**
- 新しい敵・装備・アイテムの追加が、テーブルへの 1 エントリ追加で済む形を維持する。
  そうなっていなければ設計を直す。
- 演出は最後。ゲームプレイが面白くなる前に見た目を磨かない。
  ただし**ドット絵と歩行アニメーションは演出ではなく識別性の要件**なので Phase 1 に含める。
