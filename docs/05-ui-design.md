# 05. UI 設計

## 5.1 デザイン方針

**キャラクターと地形は後期ファミコン期のドラゴンクエスト風ドット絵。UI は現代的。**

この2つを混ぜるのは折衷ではなく、それぞれに向いた仕事をさせるため。

- **盤面**（キャラ・地形）はドット絵 — 少ない情報量で「何がいるか」を一瞬で判別させる。
  ファミコン期のドット絵は、限られた解像度で識別性を最大化するために磨かれた表現形式で、
  15×15 のタイルにキャラを詰め込む本作の条件とそのまま噛み合う。
- **HUD・ログ・モーダル**は現代的なUI — HP や経験値のような**数値**を、
  当時のフォント表現で読ませる必然性はない。可読性を落とすだけになる。

演出はゲームプレイを妨げない範囲に留める（アニメーションは 200ms 以内）。

## 5.2 スプライト仕様

### 解像度とグリッド

- 1 スプライト = **16 × 16 ピクセル**（ファミコン期のキャラクタサイズに準拠）
- 1 スプライト = ダンジョンの 1 タイル
- 盤面全体 = 15 × 15 タイル = 240 × 240 論理ピクセル

### 向き

**正面向きのみ。** 上下左右で見た目は変えない。

ドラゴンクエスト1の主人公と同じ扱いで、必要な絵が最小限（キャラあたり2枚）で済む。
進行方向は移動アニメーションで表現されるため、向き別スプライトがなくても
「どちらへ進んだか」は分かる。

### 歩行アニメーション

**2 枚のフレームを切り替える。**

| 対象 | 切り替えのタイミング |
|---|---|
| プレイヤー | 移動に成功するたび |
| 敵 | その敵が移動に成功するたび |

壁にぶつかった時・攻撃した時は切り替えない（歩いていないため）。
静止中はアニメーションしない — ターン制なので、勝手に動く要素は
「時間が進んでいる」という誤ったシグナルになる。

フレーム番号は**アクターの累積歩数から導出する**。UI 側に別途アニメーション状態を持たない。

```
frame = actor.steps % 2
```

`steps` は `game/` が持つ純粋な数値（移動成功時に +1）で、DOM とは無関係。
これで「UI はゲーム状態を書き換えない」という境界（→ [02](02-architecture.md)）を保てる。

### フレームの描き分け

| フレーム | 内容 |
|---|---|
| 0 | 左足を前に出した姿 |
| 1 | 右足を前に出した姿 |

胴と頭は動かさず、**足元だけを 1〜2 ピクセル入れ替える**。
当時の 2 フレーム歩行はこの差分しか持たず、それで十分に歩いて見える。
差分を大きくすると、ターンごとの切り替えが「痙攣」に見える。

## 5.3 スプライトのデータ形式

外部画像を使えないため、ドット絵を**コード上のテキストとして持つ**。

```ts
interface SpriteDef {
  /** インデックス -> CSS 色。1スプライトあたり最大16色 */
  palette: readonly string[];
  /** frames[frameIndex][row] = 16文字の行。'.' は透明、'0'-'f' はパレット番号 */
  frames: readonly (readonly string[])[];
}
```

記述例（実際の絵ではなく形式の説明）:

```ts
const PLAYER: SpriteDef = {
  palette: ['#101018', '#f8b878', '#3860c0', '#1c3894', '#fcfcfc'],
  frames: [
    [
      '................',
      '.....000000.....',
      '....01111110....',
      '....01411410....',   // 目
      '....01111110....',
      '.....000000.....',
      '....0222222 0...',
      // ... 16行
    ],
    [ /* frame 1: 足元だけ差し替え */ ],
  ],
};
```

この形式を選ぶ理由:

- **コード上でドットを直接編集できる。** 画像編集ソフトとの往復が発生しない
- diff が読める。「どのピクセルを変えたか」が git のログに残る
- パレットを差し替えるだけで色違いの敵を作れる（Phase 3 のエリート個体で使う）

## 5.4 描画方式: SVG `<symbol>` + `<use>`

素直に 1 ピクセル = 1 `<rect>` で描くと、15×15 タイル × 256 ピクセル = **57,600 要素**になり
まったく実用にならない。これを 2 段階で削る。

### 削減1: スプライトは `<defs>` に一度だけ定義する

```html
<svg class="board" viewBox="0 0 15 15" shape-rendering="crispEdges">
  <defs>
    <symbol id="sp-player-0" viewBox="0 0 16 16"> ...rect... </symbol>
    <symbol id="sp-player-1" viewBox="0 0 16 16"> ...rect... </symbol>
    <symbol id="sp-wall"     viewBox="0 0 16 16"> ...rect... </symbol>
    <!-- 以下、必要なスプライトの数だけ -->
  </defs>

  <use href="#sp-wall"     x="3" y="4" width="1" height="1" />
  <use href="#sp-player-0" x="7" y="7" width="1" height="1" />
</svg>
```

`<symbol>` に `viewBox="0 0 16 16"` を付け、`<use>` 側で `width="1" height="1"` を指定すると、
16×16 のドット絵が 1 タイルに収まるよう自動でスケールされる。

盤面の要素数は **`<use>` が 225 個 + 定義が 20 個程度**に収まる。

### 削減2: 同じ色の横方向の連続を 1 つの `<rect>` にまとめる

1 行 16 ピクセルを 1 ピクセルずつ描かず、同色が続く区間をまとめる。

```
'....01111110....'  ->  rect(x=4,w=1,色0) rect(x=5,w=6,色1) rect(x=11,w=1,色0)
```

典型的なスプライトで 256 → 40〜70 要素程度になる。この変換は起動時に一度だけ行い、
結果の `<symbol>` 文字列をキャッシュする。

### ドットの境界をぼかさない

- ルート `<svg>` に **`shape-rendering="crispEdges"`** を指定する。
  これがないと、タイルが非整数ピクセルに拡大された時に各 `rect` の境界がアンチエイリアスされ、
  ドット絵が滲む。
- それでも隣接する `rect` の間に髪の毛のような隙間が見える場合は、
  各 `rect` の `width` / `height` を +0.02 して重ねる。

## 5.7 favicon

単一 HTML ファイルなので、外部の `.ico` / `.png` を置けない。**data URI で埋め込む。**

**プレイヤーのフレーム 0 から起動時に生成する。**

```
起動時:
  1. PLAYER.frames[0] を 16x16 の SVG 文字列に変換（盤面と同じ変換関数を使う）
  2. 背景に暗い矩形を敷く（タブの地色に埋もれないように）
  3. encodeURIComponent して data:image/svg+xml,... を作る
  4. <link rel="icon"> を document.head に挿入する
```

ドット絵を HTML 側に手書きで複製せず、**スプライト定義を唯一の出典にする**ため
この方式を採る。絵を直したら favicon も自動で追従する。

JavaScript が動かない環境では favicon が出ないが、その環境ではゲーム自体が動かないため
実害はない。

### デスクトップ（>= 900px）

```
┌───────────────────────────────────────────────────────────┐
│  DELVE          FLOOR 3   LV 5   HP ███████░░ 42/60       │  ← HUD（現代的UI）
│                 EXP ████░░ 34/60      GOLD 128    [♪]     │
├──────────────┬────────────────────────────┬───────────────┤
│  EQUIPMENT   │                            │   PERKS       │
│  ⚔ Iron Sword│                            │   Sharpened×2 │
│  ⛊ Chain Mail│      DUNGEON               │   Lifesteal   │
│  ○ Ring of.. │      15 × 15 タイル         │               │
│              │      (ドット絵 / SVG)       │───────────────│
│──────────────│                            │   ITEMS       │
│  LOG         │                            │  1 Potion ×3  │
│  > Goblin... │                            │  2 Bomb   ×1  │
└──────────────┴────────────────────────────┴───────────────┘
        Move: WASD / Arrow Keys    Explore. Fight. Descend.
```

`EQUIPMENT` / `PERKS` / `ITEMS` の各パネルは Phase 2 以降。Phase 1 は HUD・盤面・ログのみ。

### モバイル（< 900px）

サイドパネルは**タブで切り替える**（装備 / ログ）。
装備を見るのとログを読むのは別の目的なので、同時に見えている必要がない。
縦に全部積むと盤面が画面外へ押し出される。

タブの選択は設定として保存する。純粋な見た目の状態だが、
UI 側に一時的な値を抱えるより素直で、再描画で消えることもない。

縦積み。盤面を上部に置き、指で隠れない位置を確保する。

```
┌─────────────────────┐
│  DELVE   F3  LV5    │
│  HP ███░ 42/60      │
├─────────────────────┤
│      DUNGEON        │
│     (幅100%)        │
├─────────────────────┤
│  [装備][アイテム]   │  ← タブ切替
├─────────────────────┤
│  LOG (2行のみ)      │
├─────────────────────┤
│      ▲              │
│   ◀  ●  ▶           │  ← 方向パッド（タッチ時のみ表示）
│      ▼              │
└─────────────────────┘
```

ブレークポイントは **900px の 1 箇所のみ**。中間状態を増やすと検証コストが跳ね上がる。

盤面は `viewBox="0 0 15 15"` + CSS の `width: 100%; aspect-ratio: 1` で、
追加のブレークポイントなしに拡縮する。

## 5.9 フォグ・オブ・ウォー

| 状態 | 描画 |
|---|---|
| `visible` | そのまま描画。敵とアイテムも表示 |
| `explored` かつ `!visible` | 地形のみ `opacity: 0.34` で描画。敵は表示しない |
| どちらでもない | 描画しない |

暗い地下を松明で進むという状況がそのまま視界制限になっており、
ドラゴンクエストの洞窟の「たいまつ」の見え方と同じ体験になる。

## 5.9b 演出

| 演出 | 出典 | 実装 |
|---|---|---|
| 被弾（画面） | `player.hurtOnTurn === state.turn` | 盤面の縁が赤く沈む（260ms） |
| 被弾（アクター） | `actor.hurtOnTurn === state.turn` | 2回点滅（200ms） |
| ダメージ数値 | `actor.lastDamage` | 浮き上がってフェード（620ms） |
| レベルアップ | `player.leveledOnTurn === state.turn` | 中心から広がる光輪（420ms） |

**すべてゲーム状態から導出する。** `render()` が毎ターン innerHTML を作り直すので、
クラスを付けた時点で CSS アニメーションは必ず先頭から再生される。
UI 側に「今アニメーション中か」という状態を持つ必要がない。

`prefers-reduced-motion: reduce` で全て無効化される（既存の一括指定に含まれる）。

## 5.9c 効果音

Web Audio API で**生成**する。外部音声ファイルは使わないので、
鳴らせるのは矩形波・三角波・鋸波の組み合わせだけ — 当時のゲーム機と同じ制約で、
ドット絵と相性がいい。

- **既定は OFF。** 開いた瞬間に音が出るページは、それだけで閉じられる理由になる
- `AudioContext` は**最初に鳴らす時まで作らない**。ページを開いた時点で作ると
  自動再生ポリシーで suspended になったまま残る。有効化ボタンのクリックの中で作る
- 音は 0.2 秒以下・低音量に保つ。ターン制は1手ごとに鳴るので、
  長い音や大きい音はすぐ耳に障る
- 1ターンに鳴らすのは最大3種類。同じ音は1回にまとめる

`game/` は音の存在を知らない。[`ui/cues.ts`](../src/ui/cues.ts) が
ログのキーから音を引き当てる。

## 5.10 演出

すべて CSS アニメーション。JS はクラスの付け外しだけを行う。

| 演出 | 実装 | 時間 |
|---|---|---|
| 移動 | `<use>` の `x` / `y` に `transition` | 120ms |
| 攻撃 | 対象方向へ 0.2 タイル突進して戻る `@keyframes lunge` | 150ms |
| 被弾 | 赤へのフラッシュ + 微小な振動 | 200ms |
| 撃破 | `scale(0)` + `opacity: 0` | 180ms |
| 宝箱開封 | フレーム 0 → 1 へ切り替え + 光の放射 | 250ms |
| 階段降下 | 画面全体の暗転 → 新フロア表示 | 200ms |
| レベルアップ | プレイヤーを中心に広がる光輪 | 400ms |
| ダメージ数値 | タイル上に浮上してフェード | 600ms |

`prefers-reduced-motion: reduce` の環境では、すべての `animation` / `transition` を無効化する。
歩行フレームの切り替えは transition ではなく参照先の差し替えなので、この設定下でも機能する
（アニメーションではなく状態表示として扱う）。

### 演出とターン処理の関係

**演出はターン処理を一切ブロックしない。**

ターン解決は同期・即時に完了し、`render()` が状態を描き直す。演出は描画後の
見た目の変化にすぎず、演出中に次の入力が来た場合は**演出を中断して次の状態を描く**。

演出の完了を待って次のターンを受け付ける作り（アニメーションキュー）は採らない。
ターン制ローグライクの快適さは「入力に対して即座に結果が返ること」に依存しており、
150ms の待ちでも連続移動時には明確に鈍く感じられるため。

## 5.11 入力

| 操作 | キー |
|---|---|
| 移動 | `W` `A` `S` `D` / `↑` `↓` `←` `→` |
| 待機 | `.` / `Space` |
| アイテム使用（Phase 2） | `1` – `8` |
| 選択肢（Phase 2） | `1` – `3` |
| リスタート（死亡時） | `Enter` |

### キーリピートの方針

**リピートを受け付けるのは移動と待機だけ。** アイテム使用とリスタートは
「1回押したら1回」に固定する。

アイテム使用までリピートさせると、キーが張り付いた・押しっぱなしになっただけで
在庫を一息に消費してしまう。回復が最も乏しい資源である以上、
これは操作ミスではなく Run の破壊になる。

移動については、押しっぱなしでの連続移動を**許可する**
（長い通路を移動するのに毎回叩かせるのは苦痛）。ただし危険を検出したら止める。

```
リピート入力は次のいずれかが起きた時点で、そのキーを離すまで無視する:
  - プレイヤーが被弾した
  - 視界内に新しい敵が現れた
  - 階段を降りた
```

「押しっぱなしにしていたら気づかないうちに死んでいた」を防ぐ。
これは古典的ローグライクの走行中断ルールと同じ考え方。

## 5.12 アクセシビリティ

- キーボードのみで全操作が完結する。
- モーダルはフォーカストラップを持ち、`Esc` で閉じられるものは閉じる。
- 死亡モーダルは開いた時点で `DELVE AGAIN` にフォーカスを当てる
  （`innerHTML` で挿入した要素の `autofocus` は効かないため、明示的に `focus()` する）。
- **インベントリのスロットには `aria-label` を付ける。**
  アイコンは `aria-hidden` なので、ラベルがないと読み上げは数字だけになり、
  何を使うボタンなのか分からなくなる（例: `Potion を使う（スロット 1、残り 2）`）。
- 色だけに意味を載せない。HP バーには数値を併記し、レア装備は枠線でも区別する。
- 盤面の `<svg>` には `role="img"` と、現在の階層・プレイヤー位置を含む `aria-label` を付ける。
- `prefers-reduced-motion` を尊重する。

## 5.14 表示言語（EN / JA）

### 訳す範囲の線引き

| 訳さない（両言語とも英語） | 訳す |
|---|---|
| タイトル `DELVE` | ログの文章 |
| ステータス見出し `HP` `FLOOR` `EXP` `GOLD` `LV` | ヒント・標語 |
| リザルト見出し `DEPTH` `KILLS` `LEVEL` `TIME` | 設定ラベル |
| `LOG` / `YOU DIED` / `DELVE AGAIN` | 読み上げ用ラベル（aria-label） |
| 敵の名前 `Rat` `Goblin` `Bat` | タグライン |

**判断基準**: 短く、ゲームの文脈で意味が自明な語は訳さない。
`HP` を「体力」にしても読み取りは速くならず、視線が止まる分だけ遅くなる。
一方で文章は、母語で読めることに明確な価値がある。

### ログを訳せる形にする

ログは `game/` が作るが、`game/` は表示言語を知ってはいけない（→ [02 §2.1](02-architecture.md)）。
そこで **`game/` は完成した文章ではなくメッセージ識別子とパラメータだけを積む**。

```ts
// game/combat.ts
addLog(state.log, 'log.playerHit', { name: target.name, damage }, 'info');

// ui/view.ts が表示時に組み立てる
t(settings.lang, entry.key, entry.params)
//  EN: 'You hit Goblin for 7.'
//  JA: 'Goblin に 7 のダメージを与えた。'
```

言語を切り替えると、**過去のログも含めて**その場で切り替わる。
文章として保存していないため、後から言語を変えても表示が混ざらない。

### 初期値

`navigator.language` が `ja` で始まれば JA、それ以外は EN。
一度でも切り替えたらその選択を優先する（localStorage に保存）。

## 5.15 方向キーの表示切り替え

### 3つの状態

| 設定 | 挙動 |
|---|---|
| `AUTO`（既定） | タッチ端末、または画面幅 900px 未満で表示 |
| `ON` | 画面サイズによらず常に表示 |
| `OFF` | 常に非表示 |

`AUTO` の判定は **CSS のメディアクエリに任せる**。
JS で `window.innerWidth` を監視すると、リサイズと端末回転のたびに再描画が要る。

```css
.dpad { display: none; }
:root[data-dpad='on'] .dpad { display: grid; }

@media (pointer: coarse), (max-width: 900px) {
  :root[data-dpad='auto'] .dpad { display: grid; }
}
```

JS 側の責務は `<html data-dpad="...">` を置くことだけ。

### タッチ環境での配慮

- ボタンは 52〜58px 角。指で確実に押せる大きさを確保する。
- `-webkit-tap-highlight-color: transparent` と `touch-action: manipulation` で、
  タップ時の青い矩形とダブルタップ拡大を止める。
- `padding-bottom: env(safe-area-inset-bottom)` で iPhone のホームインジケータを避ける。
- タッチ環境では `WASD / ↑↓←→` のキーボード案内を隠す。押せないキーの説明は雑音になる。
- 方向パッドは **`position: sticky` にしない**。直前のヒント行に重なるため、
  通常フローの最後に置く。

## 5.16 設定の永続化

localStorage キー: `delve.settings.v1`

```json
{ "lang": "ja", "dpad": "auto" }
```

読み込み時は**既知の値だけを受け入れる**。手で書き換えられていても、
JSON が壊れていても、localStorage 自体が使えなくても、既定値で必ず起動する
（詳細は [04 §4.11](04-data-model.md)）。
