# 07. 実装ロードマップ

「機能を大量に詰め込んだゲーム」ではなく「ルールは単純だが毎回違う展開になるゲーム」を目指す。
そのため **基本ループを確実に完成させてから要素を積む**。各フェーズの終わりで必ず遊べる状態を保つ。

## Phase 1 — 基本ループ ★最優先

> 移動 → 敵 → 戦闘 → 階段 → 次の階

| 項目 | 内容 |
|---|---|
| 基盤 | 型定義 / 定数 / seeded RNG / ログ |
| ダンジョン | 部屋 + 通路生成、到達可能性保証、階段配置 |
| プレイヤー | 移動、HP、攻撃力、防御力 |
| 敵 | Rat / Goblin の 2 種、`chase` AI |
| 戦闘 | ダメージ計算、撃破、死亡 |
| 階層 | 階段で次のフロアへ、敵の階層スケーリング |
| UI | SVG ボード描画、HUD、ログ、キーボード入力 |
| ビルド | 単一 HTML ファイル出力の確認 |

**受け入れ基準**: ブラウザで開き、WASD で歩き、敵と戦い、階段を降りて次の階に進み、
HP が 0 になったら止まる。この一連が破綻なく回る。

## Phase 2 — 成長とループの回収

| 項目 | 内容 |
|---|---|
| 経験値 | 撃破で獲得、レベルアップ |
| パーク | レベルアップ時の 3 択 |
| アイテム | Potion / Bomb の 2 種、インベントリ 8 スロット |
| 装備 | Weapon / Armor / Ring の 3 スロット、基本装備 |
| 死亡 | `YOU DIED` リザルト画面、`DELVE AGAIN` |
| 保存 | localStorage への Best Depth / Best Score |

**受け入れ基準**: 死んで、記録が残り、次の Run で「今回はこのビルドを試そう」と思える。

## Phase 3 — 多様性

| 項目 | 内容 |
|---|---|
| 敵 | Skeleton / Bat / Slime / Warden を追加、特殊能力の実装 |
| ボス | 5 の倍数階に出現、固有能力、確定レアドロップ |
| アイテム | Scroll / Key を追加 |
| 装備 | レア・エピック帯、特殊効果（Burn / Lifesteal / Thorns など） |
| イベント | ランダムイベント 7 種 |
| ステータス効果 | 毒 / 火傷 / 鈍足 / シールド |

**受け入れ基準**: 10 回プレイして、同じ展開が 2 回起きない。

## Phase 4 — 中毒性と仕上げ

| 項目 | 内容 |
|---|---|
| 実績 | 9 種の実績と解除演出 |
| 演出 | 攻撃 / 被弾 / 撃破 / 開封 / 降下 / レベルアップのアニメーション |
| サウンド | Web Audio による効果音（デフォルト OFF） |
| モバイル | 方向パッド、タブ切替、レスポンシブ検証 |
| 視界 | フォグ・オブ・ウォー |
| 調整 | バランス調整、UX の粗取り |

**受け入れ基準**: 「あと1階だけ」と思って実際にもう 1 回始めてしまう。

## 進行ルール

- 各フェーズの終わりで **必ず遊べる状態**にしてコミットする。壊れたまま次に進まない。
- バランス数値は `src/data/` のテーブルだけを触って調整する。ロジックに数値を直接書かない。
- 新しい敵・装備・アイテムの追加が、テーブルへの 1 エントリ追加で済む形を維持する。
  そうなっていなければ設計を直す。
- 演出は最後。ゲームプレイが面白くなる前に見た目を磨かない。
