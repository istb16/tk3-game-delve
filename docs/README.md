## 設計の基本方針

1. **ゲームループ最優先** — `探索 → 遭遇 → 戦闘 → 報酬 → 成長 → 深層 → 死 → 再挑戦` を最初に完成させ、
   その上に要素を積む。演出は最後。
2. **ロジックと描画の分離** — `src/game/` は DOM を一切知らない純粋な状態遷移。
   `src/ui/` が状態を読んで描画する。これによりロジックだけを単体で検証できる。
3. **データ駆動** — 敵・装備・アイテム・パークは `src/data/` のテーブルに定義する。
   バランス調整でロジックを触らない。
4. **ランタイム依存ゼロ** — 出荷物は `dist/delve.html` 一枚。外部ライブラリ・外部画像・外部音声を使わない。
5. **難易度は検算する** — 「深いほど難しい」を感覚で決めず、
   [`tools/difficulty-model.mjs`](../tools/difficulty-model.mjs) で数値を確認してから書く。

## 用語

| 用語 | 意味 |
|---|---|
| Floor | 階層。1 から始まり、階段を降りるごとに +1 |
| Tile | ダンジョングリッドの 1 マス |
| Actor | プレイヤーと敵の総称。タイル上に立つ行動主体 |
| Turn | プレイヤーが 1 行動 → 全敵が 1 行動、までの一巡 |
| Perk | レベルアップ時に選択する永続的な強化能力 |
| Run | 1 回のプレイ。開始から死亡までを指す |
| Margin | 難易度の指標。`(TTD / TTK) / k²`（→ [07](07-difficulty.md)） |
| TTK / TTD | 敵を倒すのに要するターン数 / 敵に殺されるまでのターン数 |
