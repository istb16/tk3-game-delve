# 06. ダンジョン生成

## 6.1 要件

1. 15 × 15 のグリッドを毎回ランダム生成する。
2. **スタート地点から階段まで必ず到達できる**ことを保証する。
3. 深い階層ほど構造を複雑にする。
4. 敵・アイテム・宝箱を到達可能なマスにのみ配置する。

到達可能性の保証は「生成してから検証して駄目なら作り直す」方式ではなく、
**構造的に保証される生成手順**を採る。リトライ方式は最悪ケースの時間が読めないため。

## 6.2 アルゴリズム: 部屋 + 通路（BSP 風の簡易版）

```
1. 全マスを wall で埋める
2. 部屋を roomCount 個、重ならないように配置する
   - 部屋サイズ: 3..6 マス四方
   - 配置失敗は最大 60 回まで試行し、置けた分で進む
3. 部屋を「生成順」に隣接ペアで L 字通路で接続する
   - 部屋 i の中心 → 部屋 i+1 の中心 を、水平→垂直 または 垂直→水平 で掘る
   - これにより全部屋が一本の鎖で必ず連結される  ← 到達可能性の根拠
4. 追加通路を floor に応じて 0..3 本、ランダムな部屋ペア間に掘る（ループを作り単調さを消す）
5. start = 部屋[0] の中心
   stairs = start から最も遠い部屋の中心（BFS 距離で決定）
6. BFS で start からの到達可能マス集合 R を求める
7. 敵・アイテム・宝箱は R から start 周辺 3 マスを除いた集合に配置する
```

手順 3 で「全部屋が鎖状に連結される」ため、手順 5 の `stairs` は必ず `start` から到達可能。
手順 6 の BFS は検証ではなく**配置候補の抽出**として使う。

### 深度によるパラメータ

```
roomCount   = clamp(4 + floor(floor / 3), 4, 9)
extraLoops  = clamp(floor(floor / 4), 0, 3)
roomSizeMax = clamp(4 + floor(floor / 6), 4, 6)
```

浅い階は部屋が少なく見通しが良い。深くなると部屋が増え、ループが生まれ、迷いやすくなる。

## 6.3 階段の決定

`start` から BFS を走らせ、距離が最大の部屋中心を `stairs` にする。
ランダムに選ぶと「降りたらすぐ階段が目の前」という退屈なフロアが生まれるため、
**必ず探索を強制する**距離を確保する。

到達距離が閾値（`width + height` の半分）を下回った場合のみ、部屋を 1 つ追加して再配置する。

## 6.4 配置ルール

| 対象 | 個数 | 制約 |
|---|---|---|
| 敵 | `min(3 + floor/2, 10)` | start から 4 マス以上離す |
| 宝箱 | `1 + rng.int(0, 2)` | 部屋の内部のみ |
| ゴールド | `2 + rng.int(0, 3)` | 通路可 |
| アイテム | `1 + rng.int(0, 2)` | 通路可 |
| 装備 | `rng.chance(0.35 + floor*0.02)` で 1 個 | 部屋の内部のみ |
| 特殊マス | イベント発生率に従い 0..1 個 | 部屋の内部のみ |

同一マスに複数のエンティティを置かない。配置済みマスは候補集合から取り除く。

start 周辺 3 マスを除外するのは、フロア開始直後に選択の余地なく戦闘が始まるのを防ぐため。

## 6.5 視界とフォグ

```
visible[i]  = プレイヤーからチェビシェフ距離 <= VIEW_RADIUS (=6) かつ 視線が通る
explored[i] = 一度でも visible になったことがある
```

- `visible` なマス: 明るく描画。敵とエンティティを表示。
- `explored` だが `visible` でないマス: 地形だけを暗く描画。敵は表示しない。
- どちらでもないマス: 描画しない。

視線判定は Bresenham 直線で壁の遮蔽を見る。厳密な FOV アルゴリズム（シャドウキャスティング）は
15×15 の規模では過剰なため採らない。

## 6.6 Bomb による壁破壊

Bomb は周囲 8 マスの壁を `floor` に変える。ただし **外周 1 マスは破壊不可**とし、
グリッド外へ抜け出す状態を作らない。

壁を壊した結果として到達不能領域が生まれることはない（開通方向にしか変化しないため）。

## 6.7 検証

生成器は以下を満たすこと。テストを書く際の受け入れ条件とする。

- [ ] 任意のシード・任意の floor (1..100) で `stairs` が `start` から BFS 到達可能
- [ ] 外周は必ず `wall`
- [ ] エンティティが同一マスに重複しない
- [ ] エンティティ・敵がすべて到達可能マス上にある
- [ ] `start` と `stairs` の BFS 距離が閾値以上
- [ ] 同一シード・同一 floor で生成結果が完全に一致する（決定性）
